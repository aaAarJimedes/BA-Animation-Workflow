# 可复用插件与工程交付

## 请求包含插件开发时

复用已经成立的工具；先查看本机版本和当前源代码，避免每个动画项目都重构插件。需开发时按可维护职责分开：着色/算法、材质迁移和还原、描边、预设序列化、中文面板与注册入口。当前例子的六模块结构是参考，不是强制模板。

转换与还原保留原始数据指针/标识，不能只按名字猜测。共享网格、共享材质、对象级材质槽需要先隔离；重复应用不增生重复描边或备份。原材质改名后仍能正确还原；工程里还有其他卡渲使用者时，不提前恢复全局引擎/显示设置。

JSON 风格先解析并验证版本、类型、有限数值、范围、阈值顺序、原生节点接口与色带等，再整体应用，防止半次写入。跨工程按明确的名称/角色/槽位策略匹配，无法匹配就保留并提示；项目整体设置的载入与仅当前材质的调节需有清楚的范围。

真实 Blender 中优先测试能避免损坏工程的行为：共享数据隔离、空槽/不支持节点保留、连续应用幂等、改名后还原、预设往返、非法预设无半次修改、算法切换参数保留、嵌套节点隔离、注册/卸载。不要只测面板是否出现或复制实现细节的断言。

安装包排除用户工程、贴图、模型、第三方未获分发权的节点库、缓存与本机配置。原创建模/着色节点库可另交付，验证其中没有无关对象、图像和外链。

## 安装与仓库同步

使用当前项目已授予的权限，在明确的 Blender 版本/用户配置中安装；保留原设置和受影响插件恢复信息，不覆盖不相关偏好。更新已加载模块时需要处理重载或重启，不能用“文件复制成功”证明新代码正在运行。

从新的 Blender 进程检查实际模块路径、版本、启用状态以及关键操作。用户当前窗口若没有重载就明确说明，后台成功不代表面板已在该窗口完成验收。

仅在本轮要求同步仓库/发布时检查正确 remote、分支、未提交用户改动、安装包内容及版本，运行相应回归；按现有授权提交/推送/发版。核对仓库提交/标签/资产与开发源码和已安装版本一致，再清理旧包。未知授权只影响对应外部操作，不阻塞本地可审查成果。

## 收尾与清理

遵守工作区现有归档规则，同一项目沿用同名 Delivery / Tools / Temp 子目录。工程与预览到 Delivery，源码与可复用工具到 Tools，日志/中间状态/必要备份到 Temp。不要将本案例任务名复制成新项目目录。

先验收交付与依赖，再清理已证明可再生的逐帧缓存、Python 缓存、空目录和已批准的旧包。移动前核对源归属、绝对目标范围、冲突与文件哈希；迁移后修正必要引用。保留唯一源素材、用户旧版本和恢复依赖；历史日志中的原路径可以作为证据保留，并给出新目录索引。

不为每个可逆步骤新增授权流程；也不把本案例批准过的旧目录清单当作其他工程的清理许可。
