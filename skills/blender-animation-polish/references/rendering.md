# 分段渲染、恢复与成片

## 先确定要出的版本

从用户最新保存/当前内存确认源工程，再建立独立渲染快照。记录源 SHA256、Blender/插件版本、正式范围、有效 FPS、相机、引擎、分辨率/采样/色彩设置、物理状态和音轨要求。快照只因打包或目录迁移改变字节时，另记录语义保护检查；不要偷偷替换运行中的源文件。

重调卡渲后用新的批次目录。续渲染先比对 manifest 的源哈希和全部输出设置，再检查已完成片段；同名且可播放不证明属于当前源。没有足够来源证据的片段不复用。用户要求先清旧片时，核对来源与授权范围，先清旧产物再启动；源工程和唯一素材不在渲染缓存清单里。

正式视频只包含正式区间。负预热用于计算，不进入视频；本案例 24 FPS、0～778 共 779 帧，时长 779/24 = 32.458333 秒，-30～-1 不计入出片。

## 内存和 C 盘空间

输出 MOV 很小但 C 盘持续下降时，同时查看 Blender 私有提交内存、系统提交量/分页文件、临时目录和实际输出增长。把 TEMP 改到 D 盘不能阻止系统分页文件增长。先确认增长来源，不默认删除缓存或关闭系统分页文件。

本案例经验证的恢复方式：正常取消单次长渲染，让视频容器收尾，验证完整可解码的末帧并记录断点；保存当前设置快照后退出渲染进程，释放提交内存。只有仍能安全推进且空间足够时维持当前进程；空间不足时优先保住已完成的片段。不直接结束进程来赌 MOV 能恢复。

后续每段使用独立 Blender 进程，本机 48 帧一段稳定完成。48 是该机器的实测批次大小，可随内存/画面复杂度调整。进程的 TEMP/TMP、Blender 临时目录、日志和分段输出均置于任务的临时盘目录；每段开始前检查剩余空间。Persistent Data 可在短批次内保留，随进程退出释放；不要把关闭它描述成解决所有内存增长的唯一办法。无需改变原 FPS、画质或系统分页设置。

分段从中间帧启动须有确定性动画状态。已视觉烘焙且物理跟随关闭的工程可直接从该段起点渲染；仍有实时模拟、运动模糊历史或时序依赖时，需覆盖相应预热/句柄并验证边界。不能通过关掉未烘焙的物理来省时间。

## 断点与拼接

每段写完后完整解码，确认唯一视频流、尺寸/FPS、目标帧数、有效递增时间戳、预期音轨数量；再写入 checkpoint。仅有文件名、容器头或 Blender 的完成日志不足以把这一段标为通过。失败时保留已验证段，隔离未完成/损坏片段；续跑前确认旧进程已退出，避免两个运行器写同一目标。

无损拼接前确认片段范围首尾相接，无重复、缺帧或旧版本；核对编码参数/配置数据。流复制不改变视频包内容，但各段的时间戳需要重基准。对有 B 帧的素材按真实 PTS/DTS 重排关系处理；不能把本案例无 B 帧的“一包一帧、PTS=DTS”假设写成通用规则。

拼接后完整解码，检查总帧数、有效 FPS、分辨率、时长、单调时间戳、无损流复制的包内容一致性，以及每个段界前后相邻画面。数值通过不能代替观察接缝；接缝截图通过也不代表整片播放验收。

静音版明确输出零音轨；本轮要求无声时不自动带入之前的 ASMR。需要 ASMR 时按已批准声音事件和时序混音，分别检查声道/采样率、时长、峰值与削波，并保持用户取消的背景声不再出现。

在完整验证后复制/移动成片到用户指定目录，跨盘先复制并校验 SHA256，再清源副本。保留分段、源指纹与 checkpoint 到对应任务档案，更新索引。确实启用了自动检查时，完成/取消后暂停它；不要只口头声称已经停止。
