# 检查、预览与最终落盘

## 随附检查脚本

`scripts/audit_scene.py` 在当前 Blender 文件生成 JSON，不保存工程、不调用 frame_set、不重新烘焙。记录全部 Action 的关键帧/采样/修饰器签名，动画绑定/NLA/驱动，骨架静置结构，时间范围、相机和物理缓存状态，贴图/声音/字体等文件与链接库可用性。可只调用其 `resource_snapshot()` 做轻量资源检查。

在确认的 Blender 可执行文件上运行，路径按新工程填写：

```powershell
& $blender -b $project --disable-autoexec --python-exit-code 1 --python $skillAudit -- --output $baselineJson
```

脚本参数必须放在 `--` 后。有已配置驱动/插件的工程，应另在正常用户配置下打开检查；`--disable-autoexec` 是只读数据快照的隔离条件，不证明依赖脚本已正确求值。未保存的 GUI 修改不能从磁盘后台读到。

用系统 Python 比较两份快照：

```powershell
& $python $skillCompare $beforeJson $afterJson --mode timing --output $comparisonJson
```

- `timing`：核对帧率、正式/预览范围、标记及物理缓存配置；允许有意的动作编辑。
- `animation`：另核对所有 Action、驱动和动画绑定；适合材料/模型改动后的保护检查。同名以外的对象/数据更换可能导致合理差异，需逐项解释，不能为了通过而删掉检查项。
- `look-only`：另核对骨架、镜头及静态变换/约束。新添描边对象可以存在，但原有对象不得消失或出现未解释的动画/相机/变换改动。两次快照须处于同一帧和子帧，否则该模式不能做可靠静态比较。

比较结果 `ok` 只覆盖所列字段。脚本不做接触检测、未全面序列化所有修改器/模拟类型/几何节点依赖，也不证明全部视觉一致。改动作时使用实际修改区域的曲线差异与求值姿态检查；不能用允许动作变化的 timing 模式证明动作保持。

## 对应本轮范围的验证

| 改动 | 需要的证据 |
|---|---|
| 拼接/时间重映射 | 边界前后位移/最短旋转步长、接触/支撑、实际连续预览、各动画时间一致 |
| 换网格保动作 | 骨架兼容数据、Action/slot/表情/约束绑定、代表性姿态、资源重开检查 |
| 手/道具修正 | 接触状态切换、实际求值腕姿、道具支撑、可见指尖、相机特写及正式帧 |
| 只改卡渲 | 动作/相机/时间保护、同帧对照、不同动作中的连续阴影/描边检查 |
| 插件更新 | 实际 Blender 行为、安装源位置与版本、重开后的操作、包/源码匹配 |

用相邻区间与角色尺度判断异常，不把某个角度/毫米数规定成所有动作的阈值。形变结果、约束和模拟可能让静态曲线签名不足以证明可见结果。

## 可追溯预览

渲染目录与具体源版本及设置绑定：源文件哈希（或有更强内容校验支持的签名）、正式帧范围、引擎、显示/曝光、相机、分辨率与采样信息写到 manifest。仅 stem/mtime 能隔离批次，不能证明内容相同。

只在受影响范围和所有相关依赖确认不变时复用旧帧；有物理/运动模糊/时序降噪时还需考虑历史状态。否则重新渲染相应区间。不要在同一编号目录混入不同工程版本或卡渲设置的帧。

动作修订先做关键连续段和全片低成本预览；如要证明全片问题已修复，应检查正式全片。只做外观调整时，可选覆盖拼接、拍手、擦衣和收尾等实际动作的连续短段。示例中的四段 2 秒是 8 秒片段预览，不能称为完整 32 秒动画。

物理解算需要从正确预热起点顺序评估；任意跳帧的静态截图不能替代这一过程。只缓存状态而未重新烘焙时如实记录。

合成后用实际视频探测核对帧率、帧数、分辨率和时长。静帧检查、连续帧接触表和播放动态分别注明是否完成；遇到工具不支持播放，保留可供用户播放的文件并清楚说明。

## 最新保存与交付

覆盖原路径前重新核对其版本。用户同步保存时比较动作/网格/材质/相机等真正相关数据；只有当前帧等界面状态不同，可把本轮修改局部合入最新保存。遇到同一数据的冲突，先保留独立修订文件，解决冲突再替换。

有权写回时备份并核验原文件，再保存最终工程；重新打开最终路径检查依赖、范围、受保护数据与一张代表画面。交付 `.blend`、对应预览、必要参数预设/插件/说明，并明确新文件是否已经在用户当前窗口打开。检查通过后无需无目的重复渲染。

## 打包与目录改名

逐个检查请求目录中的工程，不能仅验证标为“最终”的一份。记录当前源哈希，打包可内嵌的贴图、声音、字体和链接库；不能内嵌的序列、影片、模拟缓存、几何节点或插件外部文件随项目保留并改为可迁移路径。`pack_all` 执行成功不证明全部依赖已覆盖。

区分真实引用和追加历史：按 `ID.library` 及父库关系判断实际链接；`bpy.data.libraries` 中也可能暂留无链接 ID 的追加来源。本地数据的 `library_weak_reference` 只是追加来源记录。`blend_paths` 可能列出已不需要的旧来源地址，不能仅因这种路径不存在就误判缺资源。反过来，不能只看缺图计数就忽略影片/声音、VSE 图像序列或模拟外部缓存。已 packed 的资源允许原地址不存在；仍有实际外链则必须验证可访问性及序列覆盖。部分版本打包链接库要求先保存工程并使用相对库路径，调整后重开验证。

打包后保存并重新打开，核对实际资源与动画结构。目录移动/改名后再次从最终路径打开，更新必要输出路径/索引；先复制、核对哈希和依赖，再删除原副本。删除旧网格、旧工程或缓存按明确清单执行，只对经过确认的废弃分支下手。打包检查报告属于它记录的源指纹：后续用户再保存，旧报告只作为历史证据，不能自动证明最新文件仍已验证。
