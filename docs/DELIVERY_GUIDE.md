# 渲染规划与资源交付（0.12.0）

在 `N → BA 动画 → 渲染规划与资源交付` 使用。

## 检查与打包

“检查外部资源”把结果写入文本编辑器的 `BAW_外部资源检查`。区分内嵌素材、可打包素材、缺失素材、必须另附的文件和需人工核验的缓存。追加模型留下的 LibraryWeakReference 是来源记录，不等于当前需要加载的链接库；真实 Library 仍会被检查。

“安全打包资源”处理本地普通图片、声音和字体。先检查缺失项和文件可读性，失败时回滚本轮新增内嵌数据。不会保存、覆盖原工程、清理网格或修改动作。链接库、视频、序列、UDIM 和缓存按报告处理，不能把按钮返回成功理解为所有资产都已内嵌。打包后另存，改名或迁移后重新打开，检查报告与代表画面。

## 分段计划

先保存当前工程，再导出 JSON。明确选择正式出片范围；工程中的预热帧保留，是否输出负帧由所选范围决定。48 帧来自本机案例，可按内存与单帧耗时调整。计划保留原帧率和 fps_base，记录源 SHA256、场景、采样、分辨率、连续帧段和资源报告；已有同名计划不会被覆盖。

**这是规划与预检功能，不会启动渲染、续渲或拼接。** 使用外部执行器或手动按计划执行。实时刚体、帧步长跳采样和已识别的其他模拟会阻止独立分段规划；这不能替代对插件驱动或其他时序依赖的人工判断。可调用模块 `check_source(plan)` 检查恢复前源文件是否相同，计划要求可枚举的实际依赖全部内嵌，避免外部贴图变化却未改变源哈希；自定义插件路径仍需人工确认。

本项目验证过的执行方法：每段独立 Blender 进程；把 TEMP、TMP 和 Blender 临时目录放在有足够容量的工作盘；保留原采样和分辨率。启用持久数据时也只在单个有界进程内保留，不通过修改系统页面文件解决渲染积累。

重调卡渲后使用新源快照和新输出目录，不复用旧段。完整封口的视频才能验证；逐段解码并核对帧数后记录断点。全部段齐全后，无损拼接必须满足编码参数和时间戳条件；最终仍需全片解码、帧率/帧数/分辨率/音轨检查及接缝复核。无声与音效版分别确认，不沿用旧请求的音轨。

## 清理边界

把最终工程、已交付视频、源快照、已验证分段和必要备份视为受保护数据。清理无用日志、未完成旧输出和重复安装包前，先核对路径、哈希与替代文件。用户自行移走成片时保留现状，不自动重建。
