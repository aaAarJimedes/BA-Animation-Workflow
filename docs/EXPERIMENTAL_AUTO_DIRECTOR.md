# 实验性 AI 自动导演

适用版本：Blender 5.1.2、BA Animation Workflow 0.9.0、Proscenium Hosted 0.4.0、Proscenium Motion Bridge 0.9.1。

0.9.0「实验：防接缝突变」新增过渡方式，仍默认关闭，启用后的默认方式为「仅当前段」。总过渡帧数默认 10（4–60），不是每段各自长度。

- 仅当前段：只修改当前段开头，继承前段姿态与速度后平滑回归当前动作，前段不变。
- 前后均分：总长 10 帧时前后各分配 5 帧；11 帧分配为前 5、后 6。短片段会缩短总窗口；通过位置 Hermite / 旋转球面曲线共同调整前段末尾和当前段开头。两段共用同一边界姿态；不修改窗口外关键帧和手柄。

均分会创建前段、后段原版 Action 成对备份。重复映射、改长度、切回单侧或关闭后重新映射，先撤回旧的前段窗口修正，再从干净源动作计算；不会叠加修改。若备份缺失、前段窗口后来被手动编辑、Action 被其他模型共用或两个接缝窗口重叠，会停止保护数据。若要重映射已作为均分前段的动作，请先在其后一段关闭防突变并重新映射以恢复该对动作，再修改前段。

这两种方式都仅在动作复用的映射/导入时应用，不影响生成流程。只写共同骨骼通道；无相邻前段、窗口过短或无共同通道时跳过。均分适合最后整理接缝，会修改前段已经确认的姿态，接触物体或落脚关键动作需检查。

开关后需要重新映射，不是实时预览开关。会保留 `_防突变对比_关闭` Action，取消勾选后再次映射可恢复关闭效果。与防脚滑同时开启时，防突变最后处理，开头窗口优先连续性，足部锁定可能暂时放松；窗口后维持防脚滑结果。现有活动腿约束仍受防脚滑安全检查保护，不会自动关闭用户约束。该功能不会回头修正上一接缝或自动更新下一段，请按时间顺序处理受影响片段。

0.8.8 已修复防脚滑的膝盖侧向扭曲：保留并整体转动原腿弯曲平面，再在该平面内屈膝；伸直附近采用解剖铰链方向与微小弯曲保护。

「实验：防脚滑」仅在动作复用的重新映射、单段导入和批量导入时应用，默认关闭，不介入自动生成。选择文本和目标模型后勾选开关，再执行映射/导入；关闭后再次执行即可对比关闭效果，不是实时切换。每次开启都会保存一个 `_防脚滑对比_关闭` Action，不参与文本关联或批量复用索引。

实验算法先统一父级根平移与角色水平朝向，再根据参考脚的低位、低速及持续稳定区间识别支撑，以短过渡烘焙腿链旋转；抬脚区间保留原腿部旋转。不创建永久 IK，不拉伸骨骼、不修改源动作或其他段关键帧。目前限定可识别、无活动腿部约束的 MMD FK 腿链，不支持的绑定会停止。腿长可达范围、脚尖旋转、接触识别误差仍可能留下少量滑动；并非地形感知或生产级足底解算器。

0.8.6 已有行为：选择动作文本块同步时间轴与关联 Action；持续继承位置和水平朝向，根骨俯仰/侧倾差在首帧短过渡后释放。

## 目标与边界

该面板把现有稳定组件串成一条可观察的自动流程：

```text
用户模型与创作描述
→ 本地导演方案
→ 可选的程序化场景 / 灯光 / 镜头
→ Proscenium 官方骨架 AI 动作
→ Preview
→ Proscenium Motion Bridge
→ 用户角色独立 Action
```

动作推理由 Proscenium 完成。0.9.0 使用 Blender 原生 Text 数据块保存当前 Clip，但把全部文本作为一个动作段提交。提示词内部的 Timeline、Pose Anchors、FPS、帧范围、总帧数与分段标题都不再参与调度。Text、已接受源 Action 与角色输出 Action 共享稳定 Clip ID；Text 保存每个目标模型当前采用的输出 Action。打开工程以及点击动作复用按钮时都会重新校验实际源提示词；真实源提示词优先于旧 Clip ID。覆盖旧输出前必须再次确认它确实属于同一 Text；载入时会修复 BA 自有 NLA 条带中帧段与 Action 不一致的旧版错误。独立“动作复用”面板可按文本块直接找回动作，也可把一段或同一旧模型的全部 Clip 导入空白新模型，不重新调用生成服务。

唯一的时间长度来源是面板“当前 Clip 总帧数”；帧率沿用当前 Blender 场景。若当前帧为 100、总帧数为 150，实际生成范围固定为 100–249。整体位移由面板选项决定，不从提示词解析。

起始方式由插件自动判断：目标没有已有动作，或当前帧位于时间轴起始时，启用“负滚动过渡边距”。例如当前帧 100、过渡边距 60，正式动作仍从 100 开始，物理预热从 40 开始，`40–99` 全部用于从初始姿态平滑进入动作首姿。当前帧就是起始帧 1 时，同样设置会从 -59 开始。若目标已有动作且当前帧不是时间轴起始，插件会捕获约束、IK/FK 与 NLA 求值后的最终可见姿态；新输出完成后，上一段 Action 连同其已有负滚动区一起放入 NLA，新 Action 被限制为从本段正式起点才参与求值。插件只在新 Action 实际拥有的骨骼上把整段局部运动增量重定位到捕获姿态，因此根位移和水平朝向会沿用上一段结果；D 骨、IK 和其他未写入辅助骨的局部状态保持不变。旧 NLA 条带在边界后停止求值，避免上一段独有通道混入新动作形成扭曲。

自动搭建场景、自动布光与自动构图默认均关闭，因此主运行键默认只生成角色动作。需要 blocking 或快速预览时再单独勾选。

该版本不会生成任意写实建筑或复杂道具，也不会替代角色美术、手指/表情、武器接触、裙发物理和最终人工验收。目标是先提供一条稳定、透明、可扩展的自动制作主干。

## 使用步骤

1. 在工程副本中导入用户模型，选择人体 Armature。
2. 打开 `N → BA 动画`，选择“全自动”模式。
3. 把时间轴移到当前 Clip 的正式起点，指定角色骨架，点击“新建并打开多行提示词”，然后在拆分出的文本编辑器中粘贴这一段的提示词。例如：

   `角色警惕地向前走两步，停下，突然转身看向右侧；夜晚街道，冷色霓虹，动作镜头`

   多行内容会原样保留并随 `.blend` 保存，但整体只作为一个 Prompt Block。旧工程的单行提示会在首次新建多行文本时自动导入。随后填写“当前 Clip 总帧数”。

4. 可先运行“生成导演方案”。这一步不调用 Proscenium，也不消耗 Hosted 额度。
5. 如有需要，展开“可选 · 场景辅助”，勾选场景、灯光或构图后再单独刷新；再次运行会重建而不是复制一套对象。
6. 决定是否开启“生成后自动接受并输出”：

   - 开启：点击“运行全自动工作流”即确认生成成功后自动 Accept，并输出到用户角色。
   - 关闭：生成完成后停在 `PREVIEW_READY`，检查 Proscenium 预览，再点“接受预览并输出到角色”。

7. 检查当前 Clip；通过后把时间轴移到下一段正式起点，替换提示词，再运行一次。

## 动作复用

“动作复用”是全自动页面中的独立区块，无需展开“高级设置与辅助操作”。界面只显示当前来源与目标真正可用的操作，避免三个近似按钮同时出现。

1. 在“文本块”选择要复用的动作段，例如“第四段”。插件会自动显示它当前关联的角色输出；若输出从未成功，则直接显示已接受的 Proscenium 源 Action。
2. 检查自动恢复的“关联动作”和帧范围。旧版本留下的标签会与源动作真实提示词交叉校验；不一致的误标 Action 会被忽略。Action 下拉仍可作为旧工程的反向查找入口。
3. 选择目标模型后直接使用出现的主按钮：目标与来源相同，显示“重新映射并替换所选动作”；目标是另一模型，显示“导入所选动作”。
4. 当目标是空白新模型时，额外显示“导入来源模型全部动作”；插件会按正式帧段排序，重建首段负帧过渡、后续 NLA 和片段接缝。目标已有动作时不会显示该批量按钮，以免误覆盖。

如果 Proscenium 已经完成并接受动作，但角色映射阶段失败，选择对应 Text 后会直接关联这个“生成成功，等待输出到角色”的源 Action。选择目标模型并点击“导入所选动作”即可继续，不需要重新调用生成服务。此后 Text 会指向新输出；同一 Text 在同一目标模型上再次产生的新输出会接管活动 Action/NLA 引用，旧结果退出复用列表。

新模型导入只把旧 Action 当作关联索引，实际重定向读取已接受的干净 Proscenium 源 Action；不会读取旧模型的错误骨骼姿态，不会重命名、删除或覆盖旧模型数据。若目标模型与来源模型相同，则使用“原位重新映射并替换”，旧 Action 会保留为 `_BAW_替换前` 备份。

首次使用 Animatica Cloud 仍需用户在 Proscenium 中登录。连接失败、未登录、额度不足或服务器错误都会停止流程并保留已经搭建的实验场景，便于排错。

## 状态机

| 状态 | 含义 | 下一步 |
|---|---|---|
| `IDLE` | 尚未生成 | 输入描述并生成方案或直接运行 |
| `PLAN_READY` | 本地导演方案已写入 | 检查方案，或搭建场景/运行 |
| `SCENE_READY` | 场景、灯光和镜头已建立 | 调整描述后重建，或运行动作生成 |
| `RUNNING` | 当前 Clip 动作或 Bridge 输出中 | 等待；必要时取消 |
| `PREVIEW_READY` | 动作预览已生成但未接受 | 检查后手动接受并输出 |
| `COMPLETE` | 当前 Clip 的用户角色动作已就绪 | 检查；通过后再输入下一段 |
| `ERROR` | 依赖、连接、额度、生成或重定向失败 | 按面板错误修正后重试 |
| `CANCELLED` | 用户取消了任务 | 场景保留；可重试或单独清除 |

Proscenium 的 Generate 是模态异步操作。自动导演在另一层模态计时器中轮询 `is_generating`；不会在一次 Python 调用内 `sleep` 等待，因此 Blender 的事件循环可以继续推动 Proscenium 完成烘焙。

## 所有权与恢复

- 所有生成对象、Mesh、Light、Camera、Material、World 和方案文本都带当前 Scene UUID 与 `baw_owner` / `baw_role` 标记。
- 重新搭建只删除当前场景中 `AUTO_DIRECTOR::` 角色的对象。
- “清除实验场景”只删除这些受控对象，并恢复运行前的活动 Camera 和 World。
- 用户模型、动作、贴图、原相机、原 World、同名但无所有权标记的文本和其他插件数据不会被接管。
- 不运行全局 Orphan Purge。

## 当前模板

| 场景 | 自动生成内容 |
|---|---|
| 摄影棚 | 地面与干净背景板 |
| 教室 | 地面、墙、黑板与抽象课桌 |
| 街道 | 路面、城市体块与发光招牌 |
| 舞台 | 舞台平台与表演背景板 |
| 户外 | 开阔地面与抽象自然体块 |

所有模板都按用户角色世界包围盒缩放。自动灯光使用三点 Area Light，并在隔离 World 中设置环境色；自动相机会按特写、动作或全身意图选择焦段和位置。

## 已知限制

- 目标骨架仍需被 Proscenium Motion Bridge 识别为完整 MMD 或 Auto-Rig Pro 人体控制链；任意非标准骨架可能拒绝重定向。
- 自动导演不再从文本建立多段 Timeline 或 Pose Anchors；需要多个动作阶段时，应分别生成多个 Clip。
- Root Path 与手脚 Effector 不会从文字凭空创建。需要精确走位、坐椅、持枪或接触时，应先在 Blender 中准备约束对象。
- 每次运行只处理一个 Clip；需要多个片段时必须逐段输入、逐段验收。
- 场景模板是可用的 blocking，不是最终美术资产。
- 取消客户端等待不会取消服务器端已经开始的计算；Proscenium 会丢弃迟到结果。
