# MMD 物理与安全烘焙

在 `N → BA 动画 → MMD 物理与安全烘焙` 中选择角色，点击“读取动作与预热范围”，再使用“安全烘焙并应用”。MMD Tools 必须已启用，模型必须保留 MMD 根对象、刚体和关节。

## 使用顺序

1. 先完成角色动作。起始帧应包含已有预热姿态和过渡，例如实际存在的 −30～0 帧动作。读取范围不会添加或删除关键帧，也不会改变 FPS。
2. “检查物理条件”检查绑定、动作结构和缓存类型。刚体布局需要清理 MMD 构建状态后才能可靠测量，因此后续在隔离副本中复核。
3. “每帧子步”和“求解迭代”为 0 时沿用工程设置。增加数值不能解决刚体错位。
4. “安全烘焙并应用”启动独立 Blender 进程。期间显示采样、模拟、复核进度；按 Esc 取消。源工程在成功前保持不变。
5. 完成后，角色使用带 `_BA物理` 后缀的新 Action。原 Action 保留，实时物理暂停，物理跟随约束静音。可自由跳帧、保存、重新打开和渲染。
6. 播放检查头发、衣物、接触和转身。文本 `BAW_物理烘焙报告` 包含布局校正、求解参数、最大单帧角度及回放误差。
7. “恢复烘焙前状态”恢复原 Action、旋转模式、物理约束静音值和物理世界开关。物理 Action 保留为备用。修改身体动作后，先恢复，再重新烘焙。

恢复按钮恢复的是烘焙前状态；若原工程本来启用了异常的旧缓存，也会恢复那个开关状态。它不会把旧缓存修复成新缓存。新结果保存在骨骼 Action 中。

## 为什么使用隔离模拟

Blender 5.1 的刚体点缓存将第 0 帧用于特殊缓存信息。在负帧起始的工程中，直接使用普通点缓存烘焙可能造成第 0 帧恢复到初始刚体位置。MMD Tools 的原生烘焙入口调用的也是该缓存系统。

BA 在副本中按原帧逐帧采样骨架和运动碰撞体，保留时间驱动器的原时间含义；随后从正帧 1 开始连续求解。物理骨骼的结果映回原来的完整帧段，包括负帧和第 0 帧。源动作、相机、道具、表情、标记、正式出片范围和 FPS 均不重定时。

MMD Tools 继续负责刚体、关节和跟随约束的构建。BA 不复制它的实现，也不改写它的安装文件。模拟后会重新打开快照，将结果应用到原骨架并逐帧比较；不能一致复现的结果不会应用到工作工程。

## 刚体布局校正

只有至少 4 个不同物理骨骼的子关节锚点、至少 85% 的样本支持同一个大幅偏移，才允许统一校正。容差随骨架尺寸变化。校正仅发生在模拟副本的整组刚体和关节上，原模型不移动。

这是对统一布局错位的保守检测，不是任意模型的自动修理。普通重心偏移不会校正；疑似错位但证据不一致时停止并报告。特殊模型可关闭自动校正，但检测到明确的大幅错位时仍会停止。先修好原模型布局后再运行。

## 当前边界

- 支持 MMD 动态类型 1（物理）和 2（物理＋骨骼），包括未构建和已构建、已烘焙的内存缓存工程。
- 当前角色需要单插槽、单层、完全替换的 Action。活动 NLA 层、物理骨骼上的其他有效约束或驱动器、骨架结构动画需要先合成或固定。
- 物理范围必须覆盖完整动作、正式出片和已有预热，避免输出范围外仍受到暂停物理的影响。
- 多个相互作用的动态系统、磁盘/外部缓存、带变形修改器/形态键的碰撞体、动画化的求解参数当前会停止并说明原因。
- 结果为逐整数帧关键帧，帧间线性插值；不是可再次参与其他动态系统的点缓存。高速动作的子帧运动模糊仍需单独检查。
- 在 Blender 窗口中编辑身体动作、刚体或绑定后，必须重新烘焙。BA 能拒绝运行期间变化的输入，但不能推断后续改动是否仍适合旧物理结果。
- 逐帧一致性验证证明输出能复现模拟，不代替对动画表现、软约束效果和穿模的视觉检查。
